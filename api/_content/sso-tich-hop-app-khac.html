Tích hợp SSO cho app khác

Dành cho chủ app khác (chat, meeting, app mới sau này) muốn dùng chung đăng nhập với build-web thay vì tự làm auth riêng. Viết theo từng bước, kèm code mẫu thật lấy từ api-sso/api-gateway/api-task-management hiện có.

Cập nhật 05/09/2026 Phần web: đã chạy thật (tham khảo build-web) Phần mobile: dùng chính các endpoint hiện có, không cần thêm API

1

Tổng quan hệ thống SSO

Điều kiện tiên quyết để tích hợp: app của bạn phải chạy trên 1 subdomain của cùng domain cha với build-web/sso-web (vd chat.xaydung.vn nếu domain cha là xaydung.vn) — cookie đăng nhập chỉ dùng chung được trong phạm vi 1 domain cha.

Thành phầnVai tròBạn cần biết gì
api-ssoPhát hành/xác thực token, giữ private keyAPI thuần, gọi qua gateway — không gọi thẳng
sso-webTrang đăng nhập/quên mật khẩu dùng chungRedirect người dùng sang đây khi chưa đăng nhập
api-gatewayCổng vào duy nhất, verify JWT qua JWKSMọi request (kể cả tới api-sso) đều qua đây

6 endpoint api-sso phơi qua gateway

MethodPath qua gatewayDùng khi nào
POST/api/loginĐăng nhập — body {username, password, remember}, username nhận cả tài khoản/email/số điện thoại
POST/api/refreshLàm mới access token khi hết hạn (đọc refresh cookie tự động)
POST/api/logoutThu hồi phiên + xoá cookie
GET/api/meKiểm tra đã đăng nhập chưa + lấy thông tin user hiện tại
POST/api/forgot-passwordBody {email} — gửi email chứa link đặt lại mật khẩu
POST/api/reset-password-confirmBody {token, newPassword} — token lấy từ link email

Token là JWT ký RS256, payload access token: {user_id, full_name, user_name, role_group, type:'access'} — không có sẵn cây quyền (functions/actions), muốn có phải tự gọi GET /me.

2

Tích hợp web app

Đúng luồng build-web đang chạy thật trong sandbox — copy được gần như nguyên văn.

  1. Xin domain con + đăng ký CORS ở gateway Domain app phải là subdomain của domain cha dùng chung (để cookie Domain=.xaydung.vn đọc được). Báo cho người quản trị api-gateway thêm 1 pipeline + biến CORS riêng cho origin của bạn — không dùng chung biến CORS của app khác, vì package cors hiểu chuỗi origin là 1 origin literal, không tự tách theo dấu phẩy để so khớp động (lỗi thật đã gặp lúc làm sso-web — mỗi pipeline cần 1 biến origin riêng).
  2. Mọi request gọi API phải gửi kèm cookie 
    // axios
const apiClient = axios.create({ baseURL: GATEWAY_URL, withCredentials: true });

// fetch
fetch(url, { credentials: 'include' })
    Thiếu withCredentials / credentials: 'include' thì trình duyệt không gửi cookie httpOnly kèm request — lỗi phổ biến nhất khi mới tích hợp, biểu hiện là /me luôn trả 401 dù vừa đăng nhập xong.
  3. Chưa đăng nhập → redirect cross-origin sang sso-web 
    // Không dùng <Navigate>/router nội bộ - đích nằm khác origin
const SSO_URL = import.meta.env.VITE_SSO_URL; // vd https://sso.xaydung.vn
function redirectToLogin() {
  const redirect = encodeURIComponent(window.location.pathname + window.location.search);
  window.location.href = `${SSO_URL}/login?redirect=${redirect}`;
}
    redirect phải là 1 URL/path bạn kiểm soát được — sso-web tự chặn open-redirect (chỉ chấp nhận path nội bộ hoặc domain nằm trong whitelist cấu hình lúc build sso-web, cần báo trước domain của bạn để được thêm vào whitelist đó).
  4. Bootstrap phiên đăng nhập lúc app khởi động Gọi GET /me qua gateway 1 lần lúc app mount (không phải trong từng component con) — 200 thì lưu user vào state, 401 thì gọi bước 3. Phải phân biệt rõ 3 trạng thái loading/authenticated/unauthenticated trong state — nếu chỉ có 2 trạng thái, lúc F5 trang sẽ có 1 khoảnh khắc bị hiểu nhầm là "chưa đăng nhập" và redirect oan trước khi /me kịp trả lời.
  5. Access token hết hạn giữa chừng → tự refresh 1 lần 
    let refreshPromise = null;
apiClient.interceptors.response.use(null, async (error) => {
  if (error.response?.status === 401 && !error.config._retried) {
    error.config._retried = true;
    refreshPromise ??= apiClient.post('/refresh').finally(() => { refreshPromise = null; });
    await refreshPromise;
    return apiClient(error.config);
  }
  return Promise.reject(error);
});
    Dùng chung 1 promise đang chạy (không tạo request /refresh mới cho từng request 401 đến cùng lúc) — nhiều request song song lúc token vừa hết hạn mà mỗi cái tự gọi refresh riêng dễ sinh race, đây là bug thật đã xảy ra ở build-web trước khi có SSO.
  6. Đăng xuất POST /logout qua gateway rồi xoá state phía client — service tự thu hồi session + clear cả 2 cookie (access/refresh) theo đúng domain đã set, không cần bạn tự xoá cookie tay (không xoá được vì httpOnly).
Không tự làm form đăng nhập riêng. Mọi app dùng chung đúng 1 trang login (sso-web) — nếu app bạn cần giao diện khác biệt (branding riêng), trao đổi trước với đội SSO thay vì tự dựng form gọi thẳng /api/login, để tránh mỗi app một kiểu xử lý lỗi/2FA sau này.

Tích hợp app mobile

Mobile không dùng lại được cơ chế cookie tự động của trình duyệt, nhưng không cần endpoint mới — dùng đúng các endpoint như web, app tự đọc token từ response rồi tự đính vào request sau. api-sso đã hỗ trợ sẵn: /me nhận Authorization: Bearer, còn /refresh//logout đọc token từ header Cookie (do cookie-parser parse) nên client tự dựng header đó được.

sequenceDiagram
  actor U as Người dùng
  participant App as App mobile
  participant GW as api-gateway
  participant SSO as api-sso
  participant KC as Keychain / Keystore

  U->>App: Nhập tài khoản/email/sđt + mật khẩu (form native của app)
  App->>GW: POST /api/login {username, password, remember:true}
  GW->>SSO: forward
  SSO-->>App: 200 {user} + header Set-Cookie: access_token=... ; refresh_token=...
  App->>App: Đọc 2 giá trị token từ header Set-Cookie
  App->>KC: Lưu access_token + refresh_token
  Note over App,GW: Request nghiệp vụ về sau
  App->>GW: GET /api/... , header Authorization: Bearer <access_token>
  GW-->>App: 200 (hoặc 401 nếu access token hết hạn)
  App->>GW: POST /api/refresh , header Cookie: refresh_token=<...>
  GW->>SSO: forward
  SSO-->>App: 200 + Set-Cookie: access_token=... (mới)
  App->>KC: Ghi đè access_token mới

Không WebView, không custom URL scheme. App tự đóng vai "cookie jar": đọc token ở Set-Cookie, cất an toàn, tự gửi lại.

Từng bước phía app

  1. Đăng nhập POST /api/login với JSON {username, password, remember: true} (remember:true để refresh token sống 30 ngày). Response 200: body là thông tin user; 2 token nằm ở header Set-Cookie (2 dòng access_token=..., refresh_token=...). Đọc giá trị token, bỏ qua các thuộc tính Path/HttpOnly/Max-Age.
  2. Cất token Lưu 2 token vào Keychain (iOS) / Android Keystore (qua EncryptedSharedPreferences) — không để ở UserDefaults/SharedPreferences thường.
  3. Gọi API nghiệp vụ Gắn header Authorization: Bearer <access_token> cho mọi request qua gateway. Gateway và middleware authenticate của các service đã đọc theo thứ tự "cookie trước, header Authorization sau" (xem authMiddleware.ts) nên không cần đổi gì phía service.
  4. Access token hết hạn (401) POST /api/refresh với header Cookie: refresh_token=<refresh_token> (tự dựng chuỗi, không phải cookie thật của OS). Response 200 kèm Set-Cookie: access_token=... mới — ghi đè access token đang lưu rồi gọi lại request gốc. Nếu /refresh trả 401 → refresh token bị thu hồi/hết hạn → xoá token, quay về màn đăng nhập.
  5. Đăng xuất POST /api/logout với header Cookie: refresh_token=<...> để service thu hồi đúng session trong DB, rồi xoá cả 2 token khỏi Keychain/Keystore.
  6. Quên mật khẩu Gọi POST /api/forgot-password {email} — người dùng nhận email, bấm link mở sso-web trong trình duyệt hệ thống để đổi mật khẩu (app không cần xử lý màn đổi mật khẩu).
Lưu ý HTTPS: ở production cookie set kèm Secure — chỉ có nghĩa với trình duyệt; client mobile tự quản token thì bỏ qua, nhưng vẫn phải gọi gateway qua HTTPS để token không đi qua mạng ở dạng rõ. Access token mặc định sống 15 phút (hoặc 1 ngày nếu remember:true) — đừng hard-code, cứ bắt 401 rồi refresh.

Lưu ý chung / lỗi hay gặp

Triệu chứngNguyên nhân thường gặp
/me luôn 401 dù vừa login xongThiếu withCredentials / credentials:'include', hoặc app không nằm trên subdomain của domain cha nên cookie không gửi kèm
CORS lỗi dù đã khai originOrigin của bạn dùng chung biến với app khác — package cors không tách chuỗi theo dấu phẩy, cần biến riêng cho từng pipeline
Redirect sang sso-web nhưng quay lại không đúng trangDomain redirect chưa được thêm vào whitelist lúc build sso-web (VITE_ALLOWED_REDIRECT_SUFFIX) — báo đội SSO thêm domain của bạn
Đăng xuất xong vẫn còn đăng nhập đượcChỉ xoá cookie phía client tay (không xoá được vì httpOnly) thay vì gọi POST /logout — phải gọi đúng endpoint để service revoke session + clear cookie đúng domain
Token verify được ở service này nhưng không được ở service khácService kia còn dùng logic cũ (so khớp secret) thay vì verify qua JWKS (jwks-rsa, biến môi trường JWT_JWKS_URI trỏ {api-sso}/.well-known/jwks.json)
Đăng ký trước khi tích hợp: báo đội SSO 3 thứ — domain con app sẽ dùng, origin cần thêm CORS, và (nếu redirect người dùng) domain/scheme cần thêm vào whitelist redirect — để tránh vướng ở bước cuối lúc demo.
